# dsh-debate v0.1 插件架子 Spec

Status: ready-for-agent

## Problem Statement

面对开放性论证题（没有唯一标准答案、但有好坏之分，如技术选型、架构评审），
单次模型回答存在早停、视角坍缩、依据混杂三类缺陷。
用户需要一个 DSH 原生插件：用建构 / 挑战 / 制图三角色跑辩论，
产出一套固定的五件套成果地图，而不是一个结论句。

## Solution

开发 `@doubleelec/dsh-debate` 原生插件（对标 dsh-workspace-explorer 的单包形态）：
输入框内"⚔ 辩论"按钮（有草稿才亮）为唯一入口，点开全配置对话框（只留三模型与轮数，
问题/题型/视角/背景执行时从当前会话自动判断）。
执行链为 debate_open → debate_round → debate_synthesize 三步工具，模型一步步调，
每步全文自然进会话（动态显示），面板轮询做汇总展示。

## User Stories

1. 作为提问者，我想要点 header 的辩论按钮就打开全配置对话框，以便所有选项一目了然、不用记命令。
2. 作为提问者，我想要在输入框写好问题后点 dock 小按钮自动抓草稿当问题，以便顺手开辩。
3. 作为提问者，我想要对话框里选题型（选型 / 评审 / 权衡 / 因果）后视角开关自动切换，以便不用手填维度。
4. 作为提问者，我想要视角开关可增删（至少保留一个），以便这次特殊的维度能补上、不相关的能去掉。
5. 作为提问者，我想要分别为建构者、挑战者、制图员选模型，以便默认单模型省钱、撞盲区时换双模型。
6. 作为提问者，我想要配最大轮数（1~10，默认 5），以便控制 token 花费。
7. 作为提问者，我想要裁判默认关闭、按需打开，以便平时只拿地图、要拍板时才要倾向性意见。
8. 作为提问者，我想要建单后按提示发一句话就让模型接手执行，以便不用懂工具调用细节。
9. 作为提问者，我想要面板里看到实况 transcript（分轮次与角色），以便审计辩论过程。
10. 作为提问者，我想要最终拿到五件套成果地图（视角清单、论证表、依据表、分歧地图、缺口清单），以便拿着地图做判断而不是接受一句话结论。
11. 作为提问者，我想要双方自报模型一致时直接停并提示路由未生效，以便不浪费轮次在"自己跟自己辩"上。
12. 作为提问者，我想要中途能点停止终止辩论，以便跑偏时及时止损。
13. 作为开发者，我想要协议纯函数有单测覆盖，以便改判定逻辑不回归。
14. 作为开发者，我想要 `npm run build` 一次通过且 bundle 格式符合 loader 约定，以便 dev 联调只刷页面不排障。

## Implementation Decisions

- 插件为原生单包形态：Host 半区（状态路由 + 模型工具）加浏览器 bundle（面板），构建产物为约定的 loader 格式，包名与 bundle id 一致。
- Host 暴露三条状态路由：建单、查状态（含 transcript 与地图）、停止；只做参数校验与状态存，不直接起子 agent。
- 执行链：插件注册一个模型可调工具，模型调用时以当前会话活体 agent 为 parent 起 one-shot 子 agent；辩手模型经 agentOptions 锁定，失败显式报错而非静默回落。
- 开题互盲并行，交锋轮串行（保证看到最新），制图为独立调用、只读实录；制图默认复用较强辩手模型但必须新开会话。
- 防呆规则：开题后比对双方自报模型回显，不一致的配置下回显相同则直接停。
- 术语以 CONTEXT.md 为准；已定决策见 docs/adr/0001~0006（地图非结论、三角色分离、混合视角、饱和停机、断言分层、制图员复用）。
- 视角模板库 v0.1 为四类种子（选型 / 评审 / 权衡 / 因果），每类只定 lens 名、挑战 checklist、证据期望；沉淀机制后续加。
- 面板只用按钮不用命令；模型下拉 v0.1 先给本地代理现有池，设置页扩展后续加。
- 单测环境在受限沙箱内无法启动（与既有插件一致，属环境限制），以正常终端运行为准。

## Testing Decisions

- 只测外部行为，不测实现细节。
- 缝一：协议纯函数（收敛判定、饱和判定、答案归一化、第五态黑话检查、配置校验、模型回显提取），用既有单测文件覆盖，已写 16 例。
- 缝二：host 路由契约（建单 / 查状态 / 停止的 ok 与 error 信封），后续补路由级测试。
- Client 面板走手工联调（dev profile 页面验证），不写自动化测试。

## Out of Scope

- 制图输出的结构化五件套解析（v0.1 先返回 markdown 文本）。
- 结构化饱和检测（新视角 / 新缺口 / 状态变化的比对，v0.1 用启发式占位）。
- 视角模板的沉淀与降级机制。
- 设置页的默认模型编辑与模型池扩展。
- 裁判角色的实际调用（v0.1 只存开关）。
- prod（3080）发布与 npm 发包。
