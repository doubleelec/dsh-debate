# 双视角辩论 Map（debate）设计文档 v0.1

> 状态：草案，已对齐方向。流程固定、内容生成；产物是地图不是结论。
> 对应 Skill 原型：`../skills/debate/SKILL.md`

## 1. 目标与问题类

解决**开放性论证题**：没有唯一标准答案，但有好坏之分；答好需要多视角覆盖，
且每条关键断言都要有依据。

- 在圈内：技术选型、架构评审、方案权衡、故障复盘、产品方向判断。
- 在圈外：有标准答案可查的题、纯创意发散、随手问答（不值得十倍 token）。

目标：输入一个问题 + 模型配置，输出**一套成果（地图）**，而不是一个结论句。

## 2. 设计原则

1. **分工治遗漏**：建构者负责填满，挑战者负责打穿，全面性由分工保证，不靠单次灵感。
2. **分层治混乱**：任何断言先分事实 / 推理 / 价值三类。辩论只筛推理层，
   事实层靠外部检验，价值层留给提问者。
3. **饱和治无底洞**：不停在"同意"，停在"无新信息"。
4. **地图代替结论**：分歧如实保留，磨平分歧是缺陷不是功能。

## 3. 五步流程（载体无关，Skill 与插件共用）

```
理解题面 → 生成视角 → 建构 → 挑战 → 合成地图
```

| 步骤 | 输入 | 输出 | 说明 |
|---|---|---|---|
| 1. 理解题面 | 原问题 | 题型 + 置信度 | 选型 / 评审 / 权衡 / 因果四类先行，低置信走动态 |
| 2. 生成视角 | 题型 | lens 清单（2~3 个） | 模板为底，模型可增补，人审一遍再开辩 |
| 3. 建构 | 问题 + lens | 答案空间（允许多候选并列） | KPI：填满，不许早停 |
| 4. 挑战 | 建构输出 | 修订表 + 缺口 | 专找四类洞（§5），必须引用对方原文 |
| 5. 合成地图 | 全 transcript | 五件套（§6） | 制图员独立会话，只读 transcript |

## 4. 三角色

- **建构者 Builder**：铺答案空间。KPI 是完备，不许提前收敛到单一结论。
- **挑战者 Challenger**：打穿映射表。KPI 是找遗漏与跳步，开火前必须复述对方最强版本
  （steelmanning），复述不对本轮无效。
- **制图员 Synthesizer（必备）**：只读 transcript 输出五件套，美德是忠实。
  默认复用较强辩手模型但**必须新开会话**，低温 + 强 schema，先引用后归纳。
- **裁判 Judge（可选，默认关）**：只在用户明确要拍板意见时开，与制图分两次独立调用，
  决断不许污染忠实。

复用规则：合成质量取决于 transcript 质量而非换脑子，所以默认复用以省成本；
当怀疑联合盲区（同厂商 / 同代 / 同语料偏好）或 transcript 超长时，换误差结构不同的模型制图。

## 5. 挑战者四类洞（通用 checklist）

1. 没覆盖的维度：lens 之外还有谁在乎？
2. 没覆盖的场景：常态 / 峰值 / 异常 / 增长（或题型对应场景）是否全过？
3. 没证据的断言：哪个"能"字没有出处？
4. 自相矛盾的推理：跳步、滑坡、偷换概念、双标。

每轮挑战必须包含：引用的对方原文 → 复述 → 反驳 / 承认缺口。没有引用=无效轮次。

## 6. 产物：五件套（格式固定，内容随题）

1. **视角清单**：有哪些 lens，各自核心主张。
2. **论证表**：每主张的支撑理由 + 反例 + 置信度。
3. **依据表**：每条关键断言标注类型（事实 / 推理 / 价值）与状态
   （已支撑 / 推断 / 缺失 / 矛盾），事实须带出处指针（如 `需求 §3.2 / 架构 §2.4`）。
   没有出处的"能"= 缺失，不许写成"能"；不许出现"大概能""基本满足"等第五态黑话。
4. **分歧地图**��哪里已一致、哪��真不一致；不一致��是事实分歧还是价值排序分歧。
5. **缺口与待查清单**：缺哪些信息、建议用什么方式补（查文档 / 跑测试 / 压测 / 找人确认）。

可选第 6 件（仅开 Judge 时）：倾向性意见 + 理由，与地图分开展示。

## 7. 视角模板库 v0.1（种子 4 类）

模板只定三样：lens 维度名 + 挑战者 checklist + 证据期望。不写死话术。
详见 `../skills/debate/references/lens-templates.md`。

| 题型 | 内置 lens | 证据期望 |
|---|---|---|
| 选型 / 方案比较 | 功能适配、成本、团队能力、运维负担、生态、风险与可逆性 | 成本给数字，候选空间须含 C 选项 |
| 评审 / 对照验证 | 指标完备、链路完备、场景完备、证据完备 | 出处到章节/图表，每格四态 |
| 权衡 / 决策 | 目标冲突、短期代价、长期代价、反事实、价值排序 | 代价两边都算，反事实必挖 |
| 因果 / 解释 | 现象、候选假设、证据链、替代解释、证伪条件 | 每个假设配证伪条件，替代解释须杀完 |

分类流程：高置信命中→模板为底+可增补 1~2 个 lens；低置信/未命中→全动态生成但须说明每个 lens 为何需要；
开辩前默认向人展示一遍，可增删。

沉淀：跑出的好 lens 一键入模板；连续三场无产出的 lens 降级为按需启用。模板存本地 yaml/md，
改模板不改流程。

## 8. 模型路由

- 默认：**单模型双角色**（同模型、新会话、不同角色 prompt）。治粗心、早停、视角坍缩，零额外成本。
- 升级：挑战者或制图员换**误差结构不同**的模型（大小配 / 强弱配 / 国内外配），治联合盲区。
- Skill 版传参：`agent(prompt, { provider, model, schema })`，`args.modelA/modelB` 传入；
  生效前提是 spawn 后端 + 本 Session 有模型选择授权 + adapter 认 route。
- 防呆：开题后双方自报模型，回显一致则停并提示"路由未生效"，不浪费轮次。
- 插件版：host 代码显式 `subagents.start("spawn", { agentOptions: { provider, model } })`，
  失败显式报错；前端下拉只列合法模型。

## 9. 终止规则：饱和即停

- 收敛（充分非必要）：双方显式 `agree=true` 且归一化答案一致。
- 停机（真正规则）：完整跑一轮无新增视角、无新增缺口、无状态变化即停。
- 上限：`maxRounds` 默认 5（约 12~13 次子调用），超限进合成，未决分歧如实保留。
- 防假共识：同意方须复述对方核心论据；`agree=true` 却写新答案视为无效。

## 10. 忠实度回检（默认开，低成本）

1. 每个"已一致"能否在 transcript 找到双方原话？
2. 每个"分歧"是否准确描述双方立场（可回抛双方确认，一方否认即打回重画）？
3. 有无第五态黑话？有即打回。

## 11. Skill / 插件映射

| 能力 | Skill 版 | 插件版 |
|---|---|---|
| 循环 | prompt 约束，易跳步 | host 代码锁死 |
| 路由 | 尽力而为，防呆停机 | 显式传参 + 报错 |
| 合成 | 主 agent 兼任制图员 | 第三次显式调用 + schema 校验 |
| 配置 | 调用参数 | 设置页 + 会话面板 |
| 沉淀 | 改 md/yaml | 设置页编辑模板 |

Skill 验证通过后协议原样搬进插件 host 循环，不浪费。

## 12. 成本与适用

- 成本：开题 2 + 每轮 2 + 合成 1，5 轮约 13 次调用，单问十倍以上。
- 适用：高 stakes 低频率（架构决策、选型、关键评审）、本来就要人肉验证的题、需要买反对意见的题。
- 不适用：日常问答、标准答案题、创意发散。
