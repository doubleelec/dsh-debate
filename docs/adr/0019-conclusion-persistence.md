# 结论落盘：整局记录进存储 + 结论文档进工作区

辩论结论原先只活在两处：host 进程内存里的 `sessions` Map,和对话区那条镜像消息。
这套安排有三个会断的地方,本条记下修法与取舍。

## 会断的三条命

| 存放处 | 宿主机重启 | 上下文压缩 | 未来会话/agent 能取回原文 |
| --- | --- | --- | --- |
| host 内存 `sessions` Map | ❌ 全丢（`unknown-id`） | 无关 | ❌ |
| 对话区镜像消息 | ✅ 留 | ⚠️ **正是压缩要吃掉的东西** | ⚠️ 只剩被改写的转述 |
| 面板 | ❌ 同内存 | 无关 | ❌ |

v4 把对话区镜像改成摘要（ADR-0017）之后,完整成果地图（实测一局约 7,000 字）
**只活在进程内存里**——这是当时最脆的一环。

最要紧的一条不是"防重启丢失",而是**防压缩**：对话区是唯一有耐久性的那份,
而它恰好是压缩设计上要吃掉的那种长文本。文件则相反:压缩之后 `read <路径>`
就能拿回逐字原文。真正的收益是把结论从"一条位于有损日志里的消息"变成
**一个有地址的产物**。

## 决定

### 1. 整局记录进 KV 单元 `dsh_session_enhance`

走存储枢纽 `ctx.get('storage')` → `backend.get('json')` → `kv.open({...})`,
`per-record` 布局（一局一条文档,每轮保存只重写这一局,不连带整表）。

后端名 `json` 有据可查:`dsh-base` 组合包里 `storage-json` 挂在 `dshHomePath('storages')`,
`storage-domain` 的 config 正是 `backend: json`。

单元名用 **`dsh_session_enhance`（下划线）**:`UNIT_NAME_RE` 实测是 `/^[a-z][a-z0-9_]*$/`,
**连字符非法**。这个坑不查就会在运行时才炸。

### 2. 刻意**不** import `@deepseek-ai/dsh-storage`

实测插件自己 `node_modules` 里那份是 `0.1.1-rc.2`,而宿主实际跑的是 `0.2.0-rc.2`
——两个版本并存。拿旧包的类型去喂新实现是埋雷,所以只按文档化的成员做**结构化鸭子类型**:
少一个成员就整体降级为"不持久化",绝不让插件加载失败。

### 3. 记录是显式白名单

`toRecord` 逐字段赋值,不做展开。`streaming`（转瞬即逝的打字机中间态）、
`mirrorToChat`（绑在发起会话上,重启后无意义）、`flush`（host 注入的钩子）一律不落盘。
**新增内存字段默认不落盘**——要持久化就得显式加进白名单,相容性因此是可审计的。

### 4. 恢复时把半途消失的局标成"已中断"

上次记 `running` 说明进程是在半途没的,那个后台任务已经不存在了。
恢复时标成 `stopped` 并在 progress 里写清原因:面板显示"还在跑"而实际永远不动,
比显示"已中断"更糟。`markInterrupted` 只碰 `running`,已完成/失败的局原样保留。

`fromRecord` 的判据只到"能不能用"这一层:关键字段缺失 / 版本超前 / 根本不是对象 → 跳过该条;
次要字段缺失一律补默认值。**多恢复一局胜过少恢复一局**,一条坏记录不该拖垮整张表。

### 5. 结论文档写进 `<targetCwd>/docs/session-enhance/`

文件名:`<日期>-<问题 slug>-<id 尾>.md`。日期+id 尾保证"同一天问同一个问题两次"
不会互相覆盖,而且能从文件名反查是哪一局。

记录里**只存相对路径**,绝对路径由 `targetCwd` + 它拼出来——工作区搬家/换机器后仍有效。

文件名净化按 Windows 的实际约束来:清 `\ / : * ? " < > |` 与控制字符、
空白折成单个连字符、首尾不留连字符/点/空格、按**码点**截断（不劈开代理对）、
清空后回落 `debate`。中文保留:问题多半是中文,换成拼音只会更难认。

文档排布按"人先读结论、再按需下钻":决策摘要 → 成果地图 → 每轮判定表 → **折叠的全文**。
全文折叠但不丢弃——文件很便宜,而"当时到底怎么说的"只有全文能回答。

### 6. 对话区镜像里带上文件路径

这是让文件**可被发现**的关键一步:镜像消息本身会被压缩,但"结论已存到 `<路径>`"
是一句短话,压缩摘要留得住它。没有这一步,文件就等于不存在。

### 7. 持久化永不拖垮辩论,但也永不静默

一局跑成功的辩论不能因为写盘失败变成失败,所以 `persist`/`writeReport` 都不抛,
只把原因记在 `session.persistError` / `session.reportError` 上,面板分别显示。
**两条原因分开存**:落盘失败要查存储后端,落文件失败要查工作区权限,合成一句就没法排查。

`pushEntry`/`setProgress` 都在同步回调里（model 事件）不能 await,所以用 host 注入的
`session.flush` 钩子把 ctx 带进来,并**合并写入**:同一局同时只允许一个写在飞,
期间的新请求只置脏标记。落后最多一次写入,不会积压成队列。

### 8. 卸载时关掉 KV 单元

用 `ctx.effect(() => () => unit.close())`。同一个单元名未关就再开是调用方 bug,
后端会直接 reject——那会让 HMR 重载后的插件**彻底没有持久化**。
（`ctx.on('dispose')` 在 cordis 4 里不存在,清理钩子是 effect 返回的 disposer。）

## Considered Options

- **只写文件,不做整局记录**:文件解决了压缩,但修不了 `unknown-id`——重启后面板仍然
  打不开旧局、也没有 id 可粘。
- **只做整局记录,不写文件**:记录是一个 JSON blob,人不好读、不可 grep、不进 git diff;
  而且它回答不了"这个结论当时是怎么推出来的"（虽然 transcript 在里面,但要先解析 JSON）。
- **用 `ctx.storageDomain`（官方"领域"层）**:它提供 schema 校验、写链、`domain/changed`。
  否决理由有两条:一是需要**运行时** import 一个本地版本落后的 DSH 包（见决定 2）;
  二是这三样我都不需要——单写者不需要写链,变更事件没有消费者,而 schema 校验我必须
  自己写（要容忍跨版本的前后相容,而不是版本不符就拒绝打开）。
- **用 `ctx.spillStore`**:它的形状是"超大工具文本 → 不透明定位符",没有列举/替换 API,
  定位符是后端相关的。用它存"可重新打开的一局"是拿错工具。
- **写文件用 `dsh-atomic-write`**:没用。报告是单次 `writeFileSync` 的产物,
  写坏了也不影响权威记录（权威记录在 KV 里）。
- **把结论文档写成 HTML/PDF**:markdown 能被 grep、能进 git diff、能被未来 agent 直接读,
  这三件事比排版重要。

## Consequences

- `unknown-id` 不再是终点:宿主重启后面板粘旧 id 仍能取到结论与全文。
- 新增 `/dsh-session-enhance/api/history` 一览,并给 `/api/state` 加了 `reportPath`/`reportRel`/
  `persistError`/`reportError`/`restored` 五个字段。
- 记录随 transcript 增长（实测一局 10 万字级）,`per-record` 布局把每次写限定在这一局。
- 白名单的代价:加了内存字段忘了加进 `toRecord`,重启后该字段会静默消失。
  这是刻意的取舍——相容性可审计,比"自动跟随结构"更可控。
- 结论文档会落在**被评审的工程**里（新增一个未跟踪文件）。这是选定的行为
  （结论属于那个工程,未来的读者在那里找),但用户需要知道:
  目录固定为 `docs/session-enhance/`,路径每次都会在面板和对话区报出来。
- 恢复的局**不会**继续跑:续跑需要重建常驻对与 parent,那是另一件事,没有冒充。
