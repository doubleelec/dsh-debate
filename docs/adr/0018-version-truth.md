# 版本真值：构建期内联 + 三方对账

面板徽标曾经会说谎：改代码 → 构建 → 刷新页面，徽标显示 `v0.3.0`，而宿主进程里跑的
辩论逻辑还是 `v0.2.0`。本条记下成因与修法。

## 成因（DSH 的加载模型，实测确认）

| 事实 | 证据 |
| --- | --- |
| 宿主进程启动时加载 `lib/index.js`，之后不再读盘 | 宿主 PID 18224 启动于 10/09 22:57；`lib/index.js` 构建于 10/10 12:13，仍正常服务请求 |
| `lib/client.js` 每次刷新页面从磁盘重新取 | 「改完直接刷新就能看到」这一实测观察 |
| DSH 没有插件热重载 | `dsh plugin --profile <n> <pnpm-args>` 只是 pnpm 包装（装插件）；`grep -E 'reload\|hotReload\|watchPlugins'` 在 DSH `lib/` 无命中 |

于是**两个 bundle 的新旧是独立的**：界面新、后台旧是稳定可达的状态，而徽标取值来自
界面 bundle，所以徽标反映的是"界面有多新"，不是"程序有多新"。

## 决定

### 1. 版本号在构建期内联（`src/version.ts` → `BUILD_VERSION`）

`BUILD_VERSION` 由 `import pkg from '../package.json'` 在**构建时**把当时的 `version`
写进代码。host 与 client 各内联一份，各自代表"我这份代码被构建时的版本"。

关键性质：**进程若加载的是旧 bundle，内联值自然就是旧版本**——宿主想谎报也没有素材，
它读不到磁盘上的新版本号（不像运行时读 manifest 会读到新值）。

### 2. host 三方对账（`/dsh-debate/api/version`）

返回 `running`（内联 = 真正在跑）+ `disk`（请求时读 `dsh.plugin.json` = 重启后会生效）
+ `bundleMtimeMs`（`lib/index.js` 的 mtime）+ `startedAtMs`（本进程启动时刻），
判定见 `assessVersions`（纯函数）：

- **mtime 晚于进程启动** → 那次构建发生在启动之后，本进程不可能包含其改动。
  这条是**版本号之外的安全网**：改了代码忘了 bump 也查得出来。
- **`disk !== running`** → 磁盘换过版本。
- 两者取或；同时成立时优先报"磁盘已是 v{disk}"（信息更具体）。

### 3. 徽标显示**正在跑的版本**，而不是磁盘版本

- 正常：`v{running}`。
- 后台版本取不到（旧宿主没有这条路由，实测返回 405）→ 显示 **`v?`**，
  绝不回落成 client bundle 自己的版本冒充后台版本——那正是原来那个谎的来源。
- 三种不一致各有独立文案，因为修法不同：
  - 后台旧 → **重启宿主**；
  - 界面旧（client ≠ running）→ **强制刷新页面**（`Ctrl+Shift+R`），不用重启；
  - 两者都对不上 → 分开提示，不混成一句"版本不一致"。

面板每 15s 取一次对账（成本 = 一次 stat + 读一个小 JSON），所以宿主重启后面板
**不用刷新**就能自己转为健康态。

## Considered Options

- **徽标直接读磁盘 manifest**：最省事，也最会骗人——旧进程照样报新版本号，把问题藏得更深。
- **靠 DSH 传入的 manifest 版本**：DSH 在启动时读 manifest，所以它手里的版本其实是真的；
  但插件拿不到这个值，且它不可观测，不如自建内联常量可控。
- **让 host 监视 `lib/` 自动重载**：DSH 无此机制；而且辩论跑一半换掉 host 代码会
  让"同一局的判定口径"前后不一致（`STOP_PROTOCOL_VERSION` 落盘正是为了防这个），
  自动重载在这个插件里是危险动作，不是便利。
- **同时并列显示三个版本号**：平时是噪音；只在**不一致时**才需要展开，
  所以常态只显示一个数字，异常时才出提示条。
- **把 build hash 也内联进来**：`mtime` 已经覆盖了"没 bump 版本"的情形，收益重复。

## Consequences

- 印在徽标上的数字**恒等于正在跑的代码版本**，且磁盘更新时明确要求重启宿主。
- 版本真值只覆盖 host 侧与界面侧；**跑一局辩论的实际口径由 `STOP_PROTOCOL_VERSION`
  单独记录**（每轮落进 `rounds[]`），两者互补：前者说"跑的是哪份代码"，
  后者说"这份代码用哪版协议判的"。
- 每次可见改动仍需 bump 版本号（约定：小改 +0.0.1、大改 +0.1.0），否则用户看到的是
  "mtime 变了但版本号没变"的提示——诚实，但不如直接 bump 清楚。
- 新增一条对外接口 `/dsh-debate/api/version`；旧宿主没有它，这本身就是 staleness 证据。
