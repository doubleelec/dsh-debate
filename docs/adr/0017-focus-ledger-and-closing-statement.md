# 焦点账本与收尾陈述：协议 v4

10-01 复盘一局**真跑**的 10 轮辩论（`debate-mv1tqgxb-2`，常驻，`stopReason=convergence`），
用它的数据定位了三个设计缺陷，本条记下修法与依据。

## 实测依据（不是推测）

一局 10 轮、题「旧闸门删除了，有没有必要建一个新的闸门？」的全部数字：

| 读数 | 值 | 说明 |
| --- | --- | --- |
| transcript 总字数 | 108,624 | 建构方 30,070 / 挑战方 71,539 / 制图 7,015 |
| `hasNewInfo=true` 轮数 | 10 / 10 | 饱和停机**一次都没触发**，只靠跑满前的共识停机 |
| 对话区镜像条数 | 25 | 每一步全文 `append`，≈10.9 万字原样灌进用户会话 |
| 建构方交棒字数 | 2,403 恒定（R2 起） | 载荷被 `HANDOFF_MAX_CHARS` 顶住，形状定型 |
| 建构方 `answer` | R2 起基本冻结 | 立场早定，后续轮次在磨措辞 |
| 引用命中率 | 43%（R1）→ 23%（R10） | 越往后越在自说自话，不是逐条回应 |
| 制图输出 | 7,015 字五件套 | 没有一句"所以呢/下一步做什么" |

三个缺陷分别对应：

1. **饱和判据形同死代码**：`detectNewInfo` 在**整篇 6000~8000 字**里找
   `缺口|缺失|新增|新发现|让步|收回|新视角|补充`，挑战者随便写点什么都会命中。
   否定关（B1）只挡得住"没有新增缺口"这种显式否定，挡不住满篇正常行文。
2. **没有焦点机制**：挑战者每轮都以"接受①②但须补三处"结尾，新条件散在正文里，
   下一轮既没有编号清单可依据，也没有"已结项不得重开"的约束，只能靠重述——既啰嗦又反复。
   10 轮里有 8 轮在逐条吸收上一轮刚提的条件。
3. **对话区没有出口产物**：镜像=全文（对话区不可读、上下文被吃光），
   而最终产物是 7,015 字结构化地图——用户读完仍然不知道"所以我要做什么"。

## 决定

### 1. 未决清单 = 焦点账本（`待决清单=` 行）

挑战者每轮在停机信号段多写一行 `待决清单=<分号分隔的未决条件>`，
host 用 `parsePendingItems` 解析（条数上限 6、单条 60 字），
`formatPendingFocus` 把它编号后**原样带进下一轮 prompt**，并附规则：
只谈清单内条目、逐条给接受/守住/部分接受、已结项不得重开、最多新增 1 条。

- 清单清了（`待决清单=无`）→ `[]`，配合 `agree` 走共识收敛。
- 清单**连续两轮逐条相同** → `pendingStalled` 成立，判焦点停滞停机。
- **没写这一行** → `null`（未提供），回落旧行为，不当作"谈完了"。
  这个三态区分（`null` / `[]` / 有内容）是关键：把"模型没守约"和"模型说谈完了"混为一谈
  会让停机判据在模型漏写时静默变成"永远收敛"。

选"模型自报 + host 解析"而不是 host 自己抽正文，是因为 `agree=`/`answer=` 已经在
10/10 轮里被稳定守约输出——同一位置的同一机制，可预期性有实测支撑。

### 2. 新增判定只看「本轮变化」段

`toDebateRound` 改为：双方**都有**「本轮变化」段时，`detectNewInfo` 只吃这一段；
任一方缺段（旧格式/模型漏写）才回落整篇比对，保证向后兼容。

### 3. 篇幅预算进 prompt

`ROUND_DETAIL_MAX_CHARS = 1800`，结论摘要 ≤5 行、详细论证 ≤1800 字、本轮变化 ≤3 行，
并要求"不要复述对方原文超过两句、不要重抄上一轮已结项的内容"。

### 4. 对话区只镜像摘要（`chatDigest`）

进对话区的不再是全文，而是「结论摘要」前 3 行 + `当前答案`。
全文仍在 transcript（面板逐段折叠看）。对话区是读结论的地方，逐字直播归面板。

### 5. 收尾陈述单独发一条（`决策摘要`）

制图员输出改为两段：先 `## 决策摘要`（≤500 字，四小段：结论 / 关键分歧 /
主要依据 / 建议下一步，必须自足、不许"见上文"），再 `## 成果地图` 五件套。
host 用 `extractDecisionSummary` 取摘要，漏写则 `buildFallbackSummary` 用
判定数据（双方最后答案、是否收敛、未决清单、引用统计）兜底拼一段——
兜底只写有据可查的东西，不替模型编结论。

`finalStatement` 把它包成对话区最后一条消息，指向面板看完整地图。

## Considered Options

- **加一轮"总结"模型调用**：多一次模型成本与一次失败点；制图员本来就在读全文，
  让它先写一段摘要边际成本接近零。
- **host 自己写收尾陈述**：不懂论证内容，只能复读答案；退回 `buildFallbackSummary` 角色更诚实。
- **host 从正文抽未决条件**：措辞千变万化，抽取质量不可控；自报行有 `agree=` 的先例背书。
- **镜像全文 + 折叠**：对话区不是折叠容器，10 万字是不可读，不是"有点长"。

## Consequences

- `STOP_PROTOCOL_VERSION` 3 → 4（新增 `待决清单=` 解析 + 新增判定口径变化，B5 要求 bump）。
  `DebateRound` 增加 `pendingItems`；旧局该字段缺省为 `undefined`，判定时按"未提供"处理。
- 饱和停机从"基本不触发"变成两条真实通路（无新增 / 焦点停滞），预期轮数下降；
  若模型不守约输出清单，则退化为旧行为——**退化方向是"多辩几轮"，不是"误停"**。
- 分行代价：账本上限 6 条 × 60 字，最坏多占约 400 字 prompt 预算，相对 1800 字正文预算可接受。
- 面板新增：收尾陈述块（置顶 + 一键回填输入框）、每轮小结里的"未决 N 条"读数。
