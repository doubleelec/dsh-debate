# 交棒载荷瘦身：跨轮传摘要，同轮传全文

常驻辩手整场存活，每轮投进来的对方文本都会留在它的会话里，**累加**是 context 膨胀的
真正来源（第 5 轮 prompt 爆掉）。所以按"跨轮 / 同轮"切开，而不是一刀切地砍：

| 通道 | 方向 | 载荷 | 理由 |
| ---- | ---- | ---- | ---- |
| 同轮内 | 建构者本轮全文 → 挑战者 | **全文** | 挑战者必须逐条引用对方原文（钢人化复述的前提），截断会让挑战变成空炮 |
| 首次交棒 | 挑战者开题 → 建构者第 1 轮 | **全文** | 建构者第一次看到对方的挑战清单，砍掉就等于让它回应一份残缺的清单 |
| 后续跨轮 | 上一轮对方结论 → 本轮 | **瘦身** | 本轮对方的全文马上就到，旧文可回跳 transcript |

一句话规则：**对方文本首次进入本方视野传全文，此后跨轮传瘦身。**

`slimHandoff(text, HANDOFF_MAX_CHARS=2400)` 的组成：

1. `[对方自报] agree=… answer=…` 压成一行（host 已解析，正文里不再重复）；
2. `## 结论摘要` 全留；
3. `## 本轮变化` 全留（这是"演进与让步"的可读性核心，不能砍）；
4. `## 详细论证` 按剩余预算头 60% 尾 40% 截断，中间插
   `…(详细论证中段已略,全文见 transcript)`；预算不够时先砍它，前三项永远保。

实测（`slimHandoff` 真跑）：6066 字 → 803 字，**-87%**；短文本不截断、不加标记。

## 可观测

`DebateRound.builderRelayChars` 记下每轮实际投出去的交棒字数，`/api/state.rounds[]`
返回——预算有没有生效不必靠猜，能直接看数。实测一局：`relay=[3628, 2403]`。

**保底优先于上限**：`结论摘要 + 本轮变化 + 自报行` 是硬保底，若这三项本身就超过
`HANDOFF_MAX_CHARS`，则宁超不丢（只砍详细论证）。所以 `builderRelayChars` 略大于
预算值是正常现象，不是 bug——优先级是"不丢关键信息"高于"守住字数"。

## Considered Options

- **全文照传（S1 原状）**：保真最好，但 5 轮 × 双方 4000+ 字必然膨胀。
- **只传结论摘要一行**：最省，但挑战者会失去"对方上轮让步了什么"的上下文，
  退化成一问一答。
- **按 token 计费动态裁**：要 tokenizer 与 provider 记账，超出插件该管的范围。

## Consequences

- 跨轮引用旧论证时只能看到头尾，模型可能需要回读 transcript——目前辩手没有读
  transcript 的工具，所以**摘要 + 本轮变化必须自足**，prompt 里已要求写明"相对上一轮"的要点。
- 截断是启发式，长论证中段可能含关键证据；`HANDOFF_MAX_CHARS` 是唯一的旋钮，
  放大即更保真、更耗 context。
- 同轮全文意味着单轮峰值仍是两份全文；真正的上限由 `maxRounds` 与交棒瘦身共同决定。
